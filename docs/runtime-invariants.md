# Runtime 不可破坏的约束

## 调度与状态

- 只有主驱动决定继续、等待、恢复和结束。策略返回决策，不启动第二个任务循环。
- 所有模型共用同一套生命周期。提供方差异限于能力、计量和协议适配。
- 新模式默认没有任务步骤上限和总时限；可显式配置正值。单次网络请求仍有超时，暂时错误的重试仍有限。
- 一步是一次模型请求及其工具批次；网络重试不是新业务步骤。
- 模型阶段 completed 不等于业务产物验收，也不等于后处理和保存一定成功。

## 对调用方的承诺

- 连接仍可写时，每个正常返回的处理链必须发出 turn_end；预算耗尽不能静默结束、伪造成功或仅返回空回答。
- turn_end.result 必须包含 status、reason、message、run_id、step 和工具进度计数。失败或等待时 message 必须非空。
- 预算耗尽返回 failed 及具体原因；waiting、cancelled 与 failed 分开。失败提示不是助手成功答案，不写入成功回答与长期记忆。
- 已收到的 token 是草稿。只有 message 和完成终态才能作为已完成答案；客户端不得把非空草稿当成成功。
- 传输断开或进程崩溃无法保证送达终态；调用方应查询检查点。不得宣称已送达不存在的消息。
- 不承诺所有失败都可直接恢复。未知副作用、非安全边界和终态必须拒绝重放。

## 工具与恢复

- 正常电脑工具必须先持久认领稳定执行 ID，同一 ID 不得启动两次；请求摘要冲突必须拒绝。
- 执行终态未成功提交时不得返回已确认成功；重启后无法核对的进行中操作标记结果未知，不自动重放。
- 执行结果未知时停止主循环，不能交给模型自动改用新调用 ID 重做。记录查询与实际完成确认、自动恢复必须区分。

- 执行工具前必须成功写入启动检查点；数据库不可用时不得先产生副作用。
- 取消正在执行的工具时，结果默认未知。取消不等于远程操作撤销。
- 未启动、正在执行、已返回、失败和结果未知必须区分。已返回不代表业务成功。
- 网络重试不得重放已执行工具。成功轮询不得仅因参数重复被判为空转。
- 恢复认领和后继检查点创建同事务完成；版本竞争只有一个胜者，旧运行禁止再写回。
- 仅恢复完整的请求前安全边界、有补充输入的 waiting，或全部结果可由持久记录证明的已闭合工具批次。后者补齐配对后进入下一步，不重执行工具；未启动的剩余批次、未知结果和冲突结果继续拒绝。
- 最终对话写入使用稳定运行幂等键；重复保存不新增重复记录，内容冲突要报错。
- 外部服务的 exactly-once 不在保证范围内；工具必须自己提供幂等或可查询结果。

## 上下文与持久化

- 计量包含完整消息和工具定义，预留输出。累计消耗与当前上下文占用分开。
- 服务端计量仅在模板和请求语义一致时可信；估算必须标明来源，不能将图片 URL 文本长度当作媒体成本。
- 压缩不删除系统约束、当前用户输入，不切断工具调用/结果配对。
- 摘要必须限输出、能缩小上下文并满足预算；无效、截断、失败、取消或版本变化时不得覆盖原消息。
- 原始推理不得提升为答案或恢复摘要；连接密钥不写检查点。
- 检查点与事件的更新必须原子提交，schema_version 和 revision 必须保留。
- 原始任务、工具结果和历史可能包含私密信息；数据库属于私密运行数据，不提交仓库。

## 发布

- 全部会话使用同一驱动；不得重新引入隐藏的固定四轮收尾或会话开关分流。资源限制只能通过显式预算表达。
- 管理界面是当前唯一前端交付；聊天、取消和恢复接口保持可用。
- 注释解释本项目职责和约束，不以参考项目名称代替设计理由。
- 不能用“相关测试通过”替代全套测试、真实业务链路和生产上线验收。
# 本地权限与撤销补充（2026-11-13）

- 请求额外只读目录、网络或宿主机执行，必须同时满足管理员上限与绑定执行摘要的单次授权；一般确认开关关闭也不能跳过扩权确认。
- 宿主机执行默认关闭，不是隔离失败后的回退。它具有当前账户的文件及网络权限，文件撤销不能把它变成受限执行。
- 自动文件基线必须在副作用前落盘；基线失败不执行，执行后检查点失败保留不确定状态。重复执行 ID 不重建基线、不重放操作。
- 撤销先检查当前文件是否仍等于操作结束版本；发现用户改动拒绝整次撤销。恢复中断保留日志，不能把部分恢复报告为完成。
- 检查点拒绝链接、重解析目录与多硬链接文件，不读取被替换为链接的工作目录。排除项必须明确显示，不能宣称全盘撤销。
- 控制接口默认鉴权；浏览器登录采用 HttpOnly Cookie，终端采用请求头，不把访问密钥写进模型上下文或工具结果。
- 事件和检查点预算耗尽必须返回明确失败；保留终止事件的写入能力。历史清理只处理已结束且超过期限的任务，不删除未知执行证据。

# 未完成批次恢复补充（2026-11-13）

- 人工恢复只接续原批次中确定未启动的连续后缀，已确认前缀只补齐结果，不重新调用工具或模型生成替代动作。
- 未启动后缀若存在同执行 ID 的执行凭据，拒绝恢复；未知或正在执行的操作不能被当作未启动。
- 认领恢复后继与中断准备态的作废在同一数据库事务完成。准备态改为拒绝执行，关联待决/已批准授权改为取消；旧协程的启动状态转换必须失败。
- 准备态若在认领前已变为运行态，整个恢复事务回滚，不能取消授权或假报未执行。
- 后缀工具仍经过当前工具策略、文件基线和单次权限确认。旧审批不会传到新执行 ID。恢复中再次重启，继续依据新运行的检查点判断。
- 批次所属模型步骤不因恢复被重新计算；完成剩余工具后，下一次模型调用才进入下一步。

# 本地交付补充约束（2026-11-13）

- `completed` 表示本次模型任务正常结束；验收结果单列 `verification`。没有调用方明确条件时必须标记 `not_requested`，不能声称业务结果已验证。
- 文件验收只读取工作区合资格普通文件，命令验收只信任指定命令的真实工具退出证据；后续修改会使此前测试失效。模型声称“测试通过”不能代替证据。
- 截断工具调用不能执行；文本续写和接口明确上下文超限的恢复有独立次数预算，不重新引入默认任务步数限制。无法安全压缩时明确停止。
- 长输出通过私有分页产物读取，不为找回输出重跑命令；保留上限和截断状态必须显式返回。
- 完成回执必须在数据库终态之前落盘。恢复核对必须绑定执行 ID、会话、运行、操作、摘要与所有者；无回执不推断成功，也不据 PID 猜测重跑。
- 一个本地运行数据库只允许一个服务所有者。独立执行与对话任务共享会话占用，不能绕开审批、当前工具启用范围或文件检查点。
- 归档先落盘再删除数据库大字段；保留执行 ID 墓碑，归档后旧请求仍不可重新运行。未知、待审批、待输入记录不自动清理。
- 数据库准入保留终止记录空间；预算不足在副作用前停止，存储故障返回明确失败。不能承诺物理磁盘损坏时仍能持久化。

# 实任务验证补充（2026-11-13）

- 测试证据失效应依据可信文件检查点覆盖范围中的实际变化。后续只读 Python/终端核对，不能仅因工具类型潜在可写就强迫重跑所有测试。没有变化证据时保持保守。
- `workspace_changed` 由执行服务比较检查点前后覆盖文件计算，不能使用模型自述。该字段不代表排除文件、工作区外或网络状态的完整审计，不能将工作区测试验收扩大为全局副作用验证。
- Windows 子进程使用明确批准的解释器和系统目录 PATH，以及固定可执行扩展名，不继承宿主机任意搜索路径或密钥环境变量。
- 重复失败指纹忽略每次变化的执行 ID 和文件检查点 ID；这些身份字段不能使相同错误无限绕过重复失败保护。
