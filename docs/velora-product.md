# Velora 产品定义

更新：2026-11-11。本文描述当前方向；实现状态见 [Runtime 验证记录](runtime-validation.md)。

## 定位

Velora 是面向个人的 Agent 服务：通过模型、工具、长期记忆和可选语音处理用户请求。任务可以是回答问题，也可以是需要多步执行的工作。可靠推进任务、清楚说明结果和保留可追溯进度是一等能力。

产品独立定义自身需求和运行约束。技术选择服务于任务完成、上下文管理、取消、恢复和可维护性，不以复刻其他产品为目标。

## 当前交互范围

- 后端保留对话、流式事件、取消和恢复接口，CLI 或其他调用方可以使用。
- 当前唯一前端是管理界面：运行状态、记忆、角色、模型及服务配置。
- 用户聊天页面、输入框和会话切换已移除；不把重新制作聊天前端作为本轮交付。
- 长期记忆通过独立服务调用，允许管理、纠正与追溯。
- 语音为可选后处理能力，不决定任务是否已经完成。

## 产品行为

1. 普通问题应直接回答，不为简单问答引入无意义的多步流程。
2. 多步任务持续执行，默认不以固定模型请求次数或总时长强制收尾；部署方可以显式设置预算。
3. 完成、等待、取消和失败必须区分。预算耗尽也要给调用方明确、正确、非成功的返回。
4. 工具返回成功只证明该次调用的结果；业务任务完成需要对应证据。
5. 取消不承诺撤销已发生的外部操作。无法确认的结果明确标为未知。
6. 仅从安全边界恢复，拒绝盲目重放副作用。
7. 角色控制表达方式，不得削弱执行、隐私和恢复约束。

## 管理信息架构

运行后台用于查询阶段、用量、重试、压缩、工具进度及停止原因；记忆管理用于查看和纠正长期事实；角色管理用于默认角色与导入配置；设置管理用于模型、服务和可选能力。

检查点可能包含私密任务资料，不能作为公开日志暴露。管理页面的模型 completed 不能被解释为业务验收完成。

## 范围边界

暂不构建用户向工作流编辑器、角色广场或多租户运营平台。多步任务执行是核心能力，其可靠性通过测试和灰度验证，而非以无限循环或模型自述完成作为保证。
