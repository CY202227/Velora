# Agent Runtime 改造计划

状态：实施中，未完成全计划。最新决定：旧四轮路径与模式分流已移除，所有会话统一运行；本文先前灰度开关记录属于演进历史，现以 runtime-development.md 为准。

### 本次落实

已删除用户对话页面、输入框、会话切换、聊天轮询和相关状态/辅助逻辑；管理界面的角色操作改为设置默认角色，不再依赖当前聊天会话。保留运行后台、记忆、角色和设置管理，后端聊天与取消接口继续保留。

模型结果新增 finish_reason，非流式与流式提供方均传递；length/content_filter 不再作为成功回答进入后处理和业务保存，摘要也拒绝此类结果。当前采用明确失败而非自动续写，有限续写恢复仍待实现。

工具执行增加当前运行内的状态账本：not_started、running、returned、failed、result_unknown，记录轮次、调用 ID 和已返回结果。取消已启动调用时标记 result_unknown，后续未启动调用保持 not_started。工具返回不自动等同业务成功；状态账本尚不持久化。

专项与相关回归测试 57 项通过，覆盖截断响应解析、截断时不执行工具、取消时区分已启动和未启动调用。阶段 4—7 的其余工作仍未完成。

- 阶段 1：核心完成。已有单次模型运行状态和驱动适配；waiting/suspended 等完整任务生命周期属于待补部分。
- 阶段 2：部分完成。无限额默认、显式预算、独立取消接口已实现。工具超时统一策略、取消后的执行进度/结果未知记录及部分进度查询接口仍缺。
- 阶段 3：文本核心完成。支持摘要事务、原文内存保留、可配置计量扩展和计量来源。尚无标准接口自动适配、媒体摘要和持久归档；未配置同模板计量接口时不能宣称精确计数。
- 阶段 4：部分完成。仅有有限暂时网络重试；输出截断识别与恢复、上下文溢出分类恢复、重复失败与重复继续保护仍缺。
- 阶段 5：未实施。没有统一结束决策策略或业务产物验收。
- 阶段 6：未实施。没有运行检查点、持久事件日志、等待恢复和副作用幂等恢复。

核验发现：ChatResult 尚未携带 finish_reason，驱动仍可能把 length 截断的非空回答视为完成；活动任务取消没有工具执行状态账本，不能宣称取消信号已撤销外部副作用。以上应在上线前修复。

复跑当前相关测试：53 项通过。该结果不覆盖未实施能力，不等同全计划完成。后续顺序：补截断和工具取消状态 → 有限恢复/防空转 → 完成决策 → 持久化恢复 → 管理接口和管理界面观测 → 灰度。


### 第一批进展

已实现模型阶段的 RunState、RunPhase、RunOutcome 和统一驱动适配。LLMNode 将模型阶段结果转换为原有链返回值；上下文保留每次运行独立的状态，不使用驱动实例存储会话数据。此前文件拆分经整理后纳入此批。

基线核对：SSE 断开会取消后台 turn 任务；取消在模型驱动记录后继续传播。会话锁覆盖整条处理链，因此后续独立取消接口必须绕过该锁。WAIT 仅记录下一节点索引，没有持久化运行检查点。成功路径继续 PostProcess、PersistTurn、EmitReply；模型失败阻止下游。

本批不增加双驱动开关：驱动提取保持原策略，避免维护两份相同逻辑；可通过回退本批源码恢复。后续行为变更再引入灰度配置。模型阶段 completed 不表示业务任务已验收。默认四轮限制和原有 SSE 停止原因保持兼容，内部将轮数耗尽细分为 round_limit。

已完成针对模型阶段及链适配的测试；新增独立测试与现有链/工具测试一起执行。完整生产场景基准、独立取消接口、持久化恢复及后续灰度仍待实施。

## 目标与边界

### 第二批进展与启用

已接入响应 input/output/cached Token 用量，累计消耗与最近请求输入分别记录。新模式通过 `agent_runtime_enabled` 灰度，默认关闭；`agent_max_steps` 和 `agent_run_timeout_seconds` 默认均为空，不限制任务步骤数和总时长（可显式配置正值），暂时网络错误按 `agent_request_retries` 有限重试。旧模式保留原轮数语义。

新模式每次请求前检查输入预算，预留 `agent_output_reserve`，并给模型请求设置对应输出上限。容量优先使用 `agent_context_window`，未配置时尝试供应商 `/models/{id}` 扩展字段；没有可靠容量则明确停止。计量目前使用完整文本请求的保守 UTF-8 字节上界估算，实际响应 usage 用于观测；不能把 Responses 计数接口直接当作 Chat Completions 的准确计数接口。多模态计量尚不支持，明确拒绝而非漏算。

上下文压力下可裁剪较早工具结果并保持调用/结果结构与最新结果；尚未接入摘要和原始工具结果外部存储。超限时停止并保留内存运行消息，不自动删除用户或系统消息。摘要压缩、供应商专用精确计数、独立取消 API、重复失败策略、结束验收和持久化恢复仍属后续工作。当前新模式适合受控测试，不默认用于生产长任务。

保留角色、记忆、提示词装配、回答后处理和业务持久化链；将模型阶段升级为由一个调度器管理的运行过程。统一决定请求、工具执行、上下文处理、恢复、等待和结束的顺序。

首版覆盖长任务、请求前上下文控制、有限恢复、取消和明确结束原因。不引入完整插件框架、流式提前执行工具、多 Agent 编排或自动重放外部副作用。

## 当前基线

- 外层由 TurnRouter / ChainExecutor 驱动七个业务节点；同会话使用锁。
- 模型阶段默认最多四次请求，最后一轮不提供工具定义。
- 工具串行执行，错误通常作为工具结果回填；完整输出继续进入上下文。
- 最终回答非空且没有工具调用即结束模型阶段。
- WaitRegistry 仅在内存中保存后续节点位置，不是模型执行检查点。
- 工作区已有大量业务修改。此前对 llm.py 和新增 core/agent/ 的拆分未经正确理解需求就实施，尚未验证，不作为已完成里程碑。

## 不可破坏的约束

1. 单个调度器拥有运行状态迁移权；策略返回决策，不自行启动嵌套主循环。
2. 每轮请求使用同一运行状态生成消息；压缩和恢复通过统一入口更新历史。
3. 持久化日志与内存检查点有明确版本关系；不另建可独立修改的第二份权威消息历史。
4. 用户取消和硬预算优先于自动继续；继续必须附带可执行理由。
5. 工具调用与结果保持配对；最终回答、后处理、保存和发布不能重复执行。
6. 不将预算耗尽、等待、失败或取消报告为成功完成。
7. 原始推理内容不作为用户答案或持久化恢复摘要。
8. 代码命名和注释只解释本项目职责、约束及原因，不提参考项目名称。

## 目标职责

- TurnRouter：接收请求、管理同会话并发及路由运行控制信号。
- RuntimeDriver：唯一状态迁移入口，编排每个执行步骤。
- RunState：消息、步骤、用量、恢复标记、工具进度、版本和结束结果。
- ModelRunner：单次模型请求、流式事件及有限传输重试。
- ToolExecutor：准入、执行、取消、结果归一化及记录。
- ContextManager：输入预算、结果裁剪、历史压缩和有效性检查。
- RuntimePolicy：请求前、工具前后、请求失败及结束检查，返回类型化决策。
- RunStore：后续阶段的检查点和事件持久化；明确与既有对话保存的分工。

阶段一先完成数据模型和接口约定，再决定最终文件布局，不为每个职责提前建立抽象层。

范围：辨认并撤回或重新整理此前误拆分，仅处理本次引入的内容，不覆盖其他未提交修改；核对聊天入口、SSE 断开行为、保存路径、主动提醒和现有测试。

产出：可复现基线、事件顺序和兼容清单；新旧配置与数据迁移方案。

验收：普通回答、单工具、多工具、空回答、请求失败及后处理路径可验证。解决现有测试临时目录问题，区分环境失败与产品失败。

回退：本阶段不改变产品行为。

## 阶段 1：类型化运行状态与统一驱动

范围：保留原业务链，以 LLMNode 作为适配入口；建立独立 RunState、步骤结果和结束结果。先保持现有轮数、工具执行及事件行为。

执行阶段：preparing、requesting、executing_tools、checking_stop、recovering。生命周期结果：completed、waiting、suspended、failed、cancelled；budget_exhausted 等作为具体原因。上下文压缩是一项受控操作，不产生第二个任务生命周期。

验收：假模型和假工具覆盖完整事件轨迹；异常路径只有一次终态；成功回答只后处理、保存和发布一次。

回退：通过配置切回旧执行路径。阶段 0 确定如何避免长期维护两套实现。

## 阶段 2：长任务、预算和取消

范围：移除固定四轮强制收尾的默认策略；引入可配置步骤上限、总时间、调用上限，以及可用时的 Token 预算。旧 max_tool_rounds 显式配置有兼容映射和弃用说明，不能静默改变语义。

取消须走独立控制通道，不等待当前会话锁。定义用户取消、连接断开与服务关闭的差异；SSE 断开是否继续由阶段 0 核对后定案。

验收：需要超过四轮的任务能完成；取消可中断请求及重试等待；工具不响应取消时有超时与结果未知记录；预算耗尽返回部分进度和未完成原因。

回退：恢复旧预算策略；不删除已有运行记录。

## 阶段 3：每次请求前的上下文管理

实现进展：新模式已接入请求边界的事务式上下文准备。先在副本上裁剪较早工具结果；仍超预算时，选择不跨系统指令、当前用户和最新工具批次的闭合历史片段，执行一次独立无工具摘要请求。摘要输出由 `agent_summary_output_tokens`（默认 1024）限制，用量计入累计消耗但不覆盖最近任务请求占用。空摘要、工具调用、显式推理标签、不缩小或仍超预算的摘要均拒绝提交；取消、生成失败和并发消息变化不覆盖原历史。每次准备最多一次摘要，源输入自身放不下时明确停止。

压缩前原消息保留在当前 RunState.context_archive，工具原文和配对仍可检查；这不是落盘归档，也没有模型查询归档的工具，进程退出后恢复属于阶段 6。计量仍为文本保守估算；供应商专用精确计数及多模态预算尚待适配。新模式继续默认关闭。当前实现完成阶段 3 的文本上下文核心，不能标记为完整的多供应商/多模态上下文能力。

范围：统一计量系统提示词、工具定义、历史、多模态输入及生成预留。先限制大工具结果并保留原始结果引用，再按配对边界压缩旧内容。摘要保留目标、约束、已确认事实、执行结果及剩余工作。

摘要调用绕过任务主循环，单独计量和限次；提交摘要前检查运行版本、缩小效果、工具配对和取消状态。失败不破坏原历史。不支持精确计量时明确使用保守估算。

验收：单个巨大结果、多轮增长、多模态输入、无效摘要、摘要失败、压缩时取消，以及压缩后继续均有测试；不能为了重试原样重复无效压缩。

回退：停用摘要能力并明确报预算不足，保留安全输出限制。

## 阶段 4：错误分类与有限恢复

### 阶段 2—3 后续补齐

已增加 POST /api/chat/cancel，输入 session_id。取消直接作用于当前活动任务，不获取会话锁；显式取消发布 cancelled 终态并释放锁，连接断开的外部取消继续向上传播。重复取消不重复派发，排队的新回合不被当前取消误伤。该接口只报告信号是否已发出，不承诺远端工具副作用已经撤销。

增加可选 agent_token_count_path，指向同服务、接受 model/messages/tools 并返回 count 或 input_tokens 的聊天模板计量接口。此为供应商扩展契约，不是标准 /models 或 Responses 计数接口；部署前须确认其使用与生成相同的模板和工具/多模态计量。没有配置或返回无效时，文本回退估算，非文本明确拒绝。RunState.token_count_source 标记 provider 或 estimate。已有配置的计量用于原请求、裁剪候选和摘要候选，提交前完成所有异步计量及版本检查。

多模态请求在服务端计量可用时可准入，原始媒体保留；包含媒体的历史片段不会被当作文本 JSON 摘要。尚未适配媒体摘要、自动发现标准计数端点或客户端停止按钮；原始结果归档仍仅存在当前运行内存。这些限制不应被标为完整多模态支持或持久化恢复。

范围：分开传输重试、模型纠错、上下文恢复；为每种错误设次数和条件。记录错误指纹、已尝试措施和是否确有变化；增加重复调用、连续失败及重复强制继续保护。

不要将相同参数的正常轮询一律判断为空转；根据工具语义和结果变化决定。非幂等工具不得因模型请求重试而自动重放。

验收：暂时网络失败可恢复；配置或权限错误快速退出；相同失败不能无限继续；已执行工具不会因流式重试重复产生副作用。

回退：关闭自动恢复，仍保留分类错误与终态输出。

## 阶段 5：结束检查与有限扩展接口

范围：提供请求前、工具前后、请求失败及准备结束的有限接口。结束决策为 finish、continue(feedback)、wait(requirement)、stop(reason)，统一汇总后交给驱动器执行。明确多个策略之间的优先级、超时及失败处理。

普通问答默认直接收尾。提醒、文件等任务优先使用程序证据；复杂多步骤任务才选择性增加语义验收。模型自填计划状态不能单独作为完成证据。

验收：缺少产物可被要求继续；缺用户输入进入等待；空反馈不得强制继续；相同缺项有限次重试；取消和预算不可被策略绕过。

回退：禁用自定义结束策略，保留基础结束与预算判断。

## 阶段 6：运行记录、等待与恢复

本批已实施持久化基础：新增 agent_run_checkpoints 和 agent_run_events 两张增量表，沿用当前数据库与初始化。每次检查点更新与对应边界事件同事务提交，记录 schema_version、revision 和运行 ID。挂接请求前、工具启动前、工具返回后、模型终态与处理链退出；写入失败不会继续派发工具。数据库状态失败时也通过 finally 清理活动会话注册。

检查点保留模型消息、压缩档案、工具结果和运行计数，不保存连接配置；配置中的 API key 字面值会从编码内容中替换。数据可能包含用户任务资料，按现有数据库管理，尚无归档清理策略。原始推理没有进入运行消息模型。工具启动记录先于副作用执行，因此重启后运行中的调用保守标为 result_unknown，不重放。

新增管理查询 /api/debug/runtime/checkpoints 和 /api/debug/runtime/checkpoints/{run_id}，仅返回摘要、边界和工具状态，不暴露检查点消息/结果全文。replay_safe_boundary 只说明处于已提交的请求前边界且工具结果齐全，不代表已提供恢复接口，也不保证外部环境仍适合继续。

数据库重开、终态禁止重放、持久化失败阻止工具执行已测试。此批完成第六阶段的持久化记录和恢复判定基础；等待/继续 API、恢复认领并发保护、业务保存幂等及跨重启实际执行尚未完成，不能宣称第六阶段已全部交付。

范围：先核对既有存储模型，再增加版本化运行检查点与必要事件。记录请求、工具开始/结果、上下文替换、恢复及终态；不写密钥和原始推理。

恢复只从已提交边界进行。已成功的副作用不重放；结果未知的操作先查询或交给用户处理。等待用户后重新进入调度器，避免直接跳过尚未完成的模型阶段。处理后处理和业务保存的恢复幂等性。

验收：在模型请求、工具执行、结果提交、压缩和最终保存之间注入中断；重启后能解释进度，不重复写入产物或对话。

回退：关闭自动恢复，仍可读取历史运行和故障原因；数据库迁移采用增量方案。

## 阶段 7：灰度与观测

范围：先限定会话启用；记录步骤、用量、耗时、重试、压缩、停止原因和结束检查次数。管理接口和管理界面显示必要的等待、取消与未完成信息；不要求用户聊天前端。

使用同模型、同工具、同任务对照旧路径。样例覆盖普通聊天、记忆检索、提醒、文件生成、长任务、巨大结果、重复失败和主动消息。关注完成质量、成本、延迟、错误恢复与重复副作用，而非只统计文字回答成功。

验收：阶段 0 建立基准后再定量阈值；不可出现重复副作用、终态错报或跨会话状态污染。灰度稳定后删除旧驱动，避免双轨长期漂移。

## 交付顺序

第一批：阶段 0—1，完成兼容基线与统一驱动，不改变默认执行策略。

第二批：阶段 2—4，获得长任务、上下文和恢复控制。真实长任务灰度前必须一并具备预算、取消及上下文保护。

第三批：阶段 5—6，增加任务验收、等待和可恢复执行；基础运行诊断事件从第一批就保留。

第四批：阶段 7，逐步扩大并移除旧路径。

每个阶段形成独立可审查的改动。工期在阶段 0 核对存储、取消链和测试基线后估算，不预先承诺未经验证的时间。


### 默认预算纠偏

新模式开关现与步骤预算独立。启用新模式且未设置预算时，持续执行直至模型收尾、取消或不可恢复错误；不会在第 24 步或 300 秒自动停止，也不会在预算最后一步静默撤掉工具。显式预算耗尽保持未完成原因。旧模式的 max_tool_rounds 兼容行为不变。所有模型共享相同调度规则，只有容量和计量能力按提供方适配。

已增加超过 24 步仍提供工具、显式步骤耗尽及无限额模式取消的回归测试。独立取消 API、精确计数和多模态能力仍未完成，不将本次纠偏视为阶段 2—3 全部完成。


### 第四、五阶段本批进展

新增类型化结束策略接口 StopPolicy/StopDecision，驱动统一汇总 finish、continue、wait、stop。STOP 优先于 WAIT，再处理继续反馈。空反馈拒绝强制继续，默认最多三次强制继续；策略调用十秒超时，失败不会默认为验收通过。策略作为构造参数显式注入，当前生产路径未配置业务验收器；等待结果不会走成功保存，但尚不可重启恢复。

新模式拦截相同工具、相同参数连续返回相同错误三次的情况，错误匹配基于 ok=false 或 error 字段；成功轮询不会被拦截。该机制不等同所有工具的语义错误分类，尚不覆盖非连续失败循环和业务无进展。

新增 /api/debug/runtime：返回活动运行及最近 50 次运行的内存摘要，不暴露消息、参数和工具结果全文。管理页面轮询显示模型阶段、步骤、用量、重试、压缩与停止原因。记录仅反映模型阶段，不将其 completed 解释为整个业务任务验收。输出截断目前仍明确失败，续写和上下文服务端溢出恢复尚待补齐。

专项及相关回归 62 项通过。第六阶段持久化检查点与恢复尚未实施；不可标记全计划完成。


### 第六阶段恢复入口与保存幂等

新增 POST /api/chat/resume，输入 run_id，可附加 text。仅在新运行模式启用时可用。安全请求前检查点可重发模型请求；waiting 检查点必须带补充输入，继续原始任务。模型阶段从持久消息和累计计数恢复，重跑前置业务装配以加载当前连接配置；模型不匹配则拒绝执行。结果未知、非安全工具边界、终态、已认领和已脱敏丢失内容的检查点不恢复。

恢复通过 revision 比较更新原子认领源运行，并在同事务建立后继检查点和两条认领/创建事件。旧执行者无法再写回源记录；同一源只能认领一次。后继自身有独立运行 ID，后续进程中断可再从后继的安全边界认领。尚未提交的工具边界不会推测性重放。

最终对话保存接受 operation_id；运行 ID 映射稳定的用户/回答记录 ID，重复保存返回同一回答记录，内容冲突拒绝。记忆交付继续使用稳定回答 ID 作为幂等键。此机制不提供远程工具 exactly-once，也没有开放模型已完成后任意重跑后处理的接口。

本批验证实际 Router/LLM 恢复、原始目标保留、等待输入、并发认领只成功一个、拒绝旧写入、重复保存不产生多轮记录；含记忆交付的相关回归 84 项通过。仍需生产故障注入、非模型阶段恢复策略及第七阶段灰度；不将受限安全边界恢复宣称为任意指令位置无缝恢复。


### 第七阶段受控灰度

新增 agent_runtime_sessions 白名单，与全局开关分开：全局关闭时仅白名单会话进入新驱动，其余继续兼容路径。共享 Provider 按请求复制并设置输出预留，避免灰度会话污染其他会话；恢复接口也遵守相同会话准入规则。管理摘要标记 new/legacy。示例配置已更新，未自动修改真实 .env 或全局启用。

真实服务元数据发现：/models/{id} 不可用时，回退 /models 并严格匹配模型 ID；测试服务返回 odb、max_model_len=131072。新增脚本 scripts/runtime_canary.py，用合成任务和独立 .runtime-canary/canary.db 测试普通回答、工具往返、流式取消、安全检查点恢复、摘要压缩，结果写入 .runtime-canary/report.json。此为真实模型运行时冒烟，不是完整业务 API/记忆/TTS/副作用故障注入验收。

首次五个场景均通过；相关回归 86 项通过。完整套件曾得到 168 passed、1 skipped、1 failed：现有 public memory snapshot 测试调用依赖 ingest_locomo_sample 的 source_turns 参数，而本机依赖已移除此参数。此为另一个评测脚本的依赖兼容问题，未以跳过或弱化断言掩盖。全计划不能因此标记为已通过完整验收，也尚未删除兼容路径。


灰度复测最终结果：五项通过。plain 1.83 秒；tool_roundtrip 两步、一次工具调用、3.58 秒；cancel 在请求发出且尚未收到可见文字时成功取消，0.57 秒；safe_resume 1.46 秒；summary 11.13 秒，压缩后保守计量 834。中间一轮取消用例因等待首字 60 秒超时失败；已将用例修正为发出请求后取消并验证 cancelled，未将失败轮隐藏为成功，也未因此改变产品超时策略。最终结果见 .runtime-canary/report.json。
