# 终端预览版

在项目根目录运行：

```powershell
.\velora.ps1 --start-server
```

已有后端运行时直接用 `.\velora.ps1`。也可用项目解释器运行 `.venv/Scripts/python.exe -m server.terminal`；安装项目入口后命令为 `velora`。

--start-server 仅支持默认本机地址；显式启动本地服务，沿用现有 .env 和数据库设置，退出终端时停止本次启动的服务。已有服务不会被本终端停止。启动日志在 velora_data/terminal-server.log。其他地址用 --url，并单独启动对应后端。

终端不修改模型配置。全部会话已统一使用 runtime，/status 的 runtime_mode 为 unified；旧模式开关已废弃。

## 交互

直接输入请求。回答逐段显示，工具调用单独提示；中间草稿被重置时明确标记，最终回答与草稿不一致会重新展示。工具已返回不等于任务验收通过。

- /new：新会话。
- /sessions：列出会话。
- /use <session-id>：切换会话。
- /history：查看当前会话最近消息。
- /status：查看当前进程保留的运行摘要。
- /cancel：发送取消请求。
- /resume <run-id> [补充输入]：通过后端安全恢复入口继续，当前先等待完整结果，不提供恢复过程流。
- /help、/exit：帮助和退出。

输入末尾加反斜杠可续行。Ctrl+C 在生成时关闭当前流并尝试通知后端取消；输入时取消当前输入。取消不能撤销已发生的外部操作。未收到 turn_end 时明确提示完成状态未知，不自动重发。

## 会话与隐私

velora_data/terminal.json 只保存服务地址、会话 ID 和最近运行 ID，不保存凭据或聊天全文。下次连接同一服务自动继续；--new 强制新建，--session 显式指定，--persona 为新会话选择角色。

终端输出过滤模型提供的终端控制序列；不渲染任意 ANSI 指令。--no-color 可关闭本客户端颜色。

单次调用例子：

```powershell
.\velora.ps1 --new "只回复：连接成功"
```

成功退出码 0，失败、预算耗尽或缺少终态退出码非 0。真实请求会使用当前模型及业务服务，有相应推理与数据写入。

## 验证

专项测试覆盖 SSE 多行、流式不重复输出、预算失败、缺失终态、终端控制序列过滤和本地会话恢复。相关回归 94 项通过。首版未加入全屏 TUI、Markdown 富渲染和文件编辑审批交互。

隔离服务真实 HTTP 冒烟通过：终端创建会话、流式请求、接收最终回答并查询 new 模式运行状态；临时测试服务已关闭，未修改生产 .env。
# 单次执行确认（2026-11-12）

部署配置 `VELORA_EXECUTION_REQUIRE_APPROVAL=true` 时，终端在电脑工具启动前展示目标、具体请求，输入 yes 批准本次操作，其他输入拒绝。非交互终端不会自动批准。批准仅允许原沙盒内的这次请求，不解除文件或网络边界。Ctrl+C 取消当前任务；连接断开或服务重启后不能用旧审批恢复执行。

# 断线重连（2026-11-12）

常规聊天任务在断线后继续运行，输入 `/watch` 从上次游标继续查看；`/tasks` 列出当前会话任务，`/watch <task-id>` 可打开指定任务。此操作不重新提交用户需求。`/status` 查询已保存状态，`/cancel` 或 Ctrl+C 显式取消。重连可以接着处理仍有效的审批；过期或已处理的审批不会再次执行。

关闭连接与停止服务不同：后台服务必须继续存活，任务才能继续；服务重启后旧进行中任务只报告 interrupted，不自动恢复。终端自启的服务在有运行中或未确认任务时会保留。下文旧版“断线等于取消”的描述以本节为准。

# 本地控制与文件撤销（2026-11-13）

终端连接默认本机地址时自动读取 `velora_data/local-control.token`。其他地址使用 `--token-file` 显式指定访问密钥文件。管理界面首次访问需登录，可在本机运行 `velora --show-access-token` 查看密钥；不要将它发送给模型或放入日志。其他 API 客户端需携带 `X-Velora-Token` 请求头。

`/changes <执行ID>` 预览一次工具的文件改动，`/undo <执行ID>` 预览后确认撤销。`/changes-run <运行ID>` 与 `/undo-run <运行ID>` 用于整轮；只接受已结束且所有相关操作均有检查点的运行。撤销需要交互式明确确认，发现用户后续编辑会拒绝覆盖。

默认不开放额外目录、网络和宿主机权限。管理员允许后，模型仍需给出本次申请理由，终端显示具体范围，由用户逐次决定。宿主机执行会获得当前账户权限；工作目录外的改动不在撤销范围内。

# 中断任务续跑补充（2026-11-13）

`/resume <run-id>` 现在还支持“前半批结果已确认、后半批确定未启动”的工具批次。终端不会重新执行已完成工具。中断前尚未启动的准备/审批操作会被标记未执行，旧授权作废；若任务之后再次申请，仍需按当前权限范围确认。

已经启动但结果未知的操作仍拒绝恢复。恢复需要用户主动选择运行 ID；启动终端不会自动执行历史任务。

# 验收与执行输出（2026-11-13）

下一任务指定验收：`/expect [{"kind":"file","path":"result.json","contains":"ready","json_valid":true}]`。命令测试可用 `[{"kind":"command","operation":"run_shell","source":"python -m pytest"}]`。`/expect` 查看，`/expect clear` 清除；条件提交给任务后自动清除，恢复时从运行记录保留。通过时显示“指定验收条件已通过”。未指定条件的普通对话不会被标为已验收。

`/capabilities` 查询执行能力，`/execution <执行ID>` 查看状态，`/cancel-execution <执行ID>` 请求停止正在运行的单次工具，`/reconcile <执行ID>` 根据已有完成回执核对，不重跑命令。取消不撤销副作用；无法确认结果时明确显示未知。

`/output <执行ID> [字符偏移] [stdout或stderr]` 分页读取保留的命令输出。终端给出下一页命令；达到原始捕获上限时提示缺失部分不可恢复，不能通过重跑有副作用的命令找回。
